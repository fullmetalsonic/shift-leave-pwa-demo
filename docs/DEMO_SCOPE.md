# 공개 데모 포함·제외 기준

최종 갱신: 2026-08-26

## 포함하는 자료

| 구분 | 공개 내용 | 이유 |
| --- | --- | --- |
| 서비스 접속 | 운영 앱 로그인 화면 URL, 관리자 지정 이름·비밀번호 방식 | 실제 사용자가 공식 접속 위치를 찾을 수 있게 안내 |
| 화면 | 근무표(개인·전체), 휴가·대근(월간 현황·대근 등록), 일정, 역할 안내 | 제품 목적과 사용 흐름 설명 |
| 데이터 | `김하늘`, `이도윤` 등 합성 이름과 2026년 8월 예시 | 실제 개인정보 없이 화면 이해 |
| 근무 규칙 | 일반적인 4조 2교대 예시와 상주 A/B 용어 | 화면 표기 이해 |
| 상호작용 | 4개 주 메뉴, 내부 보기 전환, 날짜 선택, 대근 등록 토글, 저장 안내 | 체험 가능성 확보 |
| 설명서 | 용어, 단위, 예시, 저장 결과, 오류와 복구 | 처음 보는 사용자도 이해 |
| 시험 | 데스크톱·모바일, axe, 가로 넘침, 외부 요청 차단 | 공개물 품질과 안전성 확인 |

## 제외하는 자료

| 구분 | 제외 내용 | 위험 |
| --- | --- | --- |
| 운영 연결 | 운영 Supabase URL/ref, publishable/service-role key | 운영 시스템 식별·공격면 증가 |
| 서버 구조 | migration, RLS, RPC, Edge Function, DB 스키마 | 권한·데이터 구조 노출 |
| 개인정보 | 실명, 전화번호, 로그인 이름, 비밀번호 | 개인정보·계정 보안 침해 |
| 회사 정보 | 실제 조 편성, 휴가, 대근, 공지, 사내 기준 | 회사 운영정보 노출 |
| 운영 문서 | 감사 로그, 장애 기록, 백업·복구·배포 절차 | 내부 통제 구조 노출 |
| Git 이력 | 운영 저장소 commit, branch, issue 연결 | 삭제된 과거 정보 재노출 |
| 운영 기능 | 실제 저장, 계정 생성, 비밀번호 초기화, 복원 | 오조작과 운영 데이터 변경 |

## 분리 원칙

1. 운영 저장소를 Fork하거나 공개 상태로 바꾸지 않는다.
2. 공개 데모는 빈 디렉터리에서 새 Git 이력으로 시작한다.
3. 정적 HTML·CSS·JavaScript만 배포하며 외부 API를 호출하지 않는다.
4. 합성 데이터는 실제 사람·일정과 무관하게 작성한다.
5. 새 기능을 공개할 때마다 운영 식별자·내부 경로·개인정보를 다시 검사한다.
6. 공개 설명과 실제 운영 기능이 다르면 데모 한계를 명시한다.
7. 운영 앱 주소는 공개할 수 있지만 실제 로그인 이름·비밀번호·사용자 목록과 관리자 기능 사용법은 공개하지 않는다.
