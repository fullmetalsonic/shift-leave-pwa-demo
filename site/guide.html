01

공통 사용법

주 메뉴는 근무표, 휴가·대근, 일정, 더보기 4개입니다. 근무표 안에서는 내 근무표/전체 근무표를, 휴가·대근 안에서는 월간 현황/대근 등록·지원을 바꿔 봅니다. 각 화면의 파란 안내 상자에는 화면 목적과 반드시 알아야 할 내용이 항상 표시됩니다. 긴 순서는 이 화면 사용법을 펼쳐 확인합니다.

상태 구분

주의 · 저장 가능 확인 후 계속할 수 있습니다.

저장 불가 · 입력 수정 필요 필수값을 고쳐야 합니다.

02

내 근무표

본인의 기본 근무와 휴가·대근·교육·지원 기록을 날짜별로 봅니다.

  1. 달력에서 날짜를 선택합니다.
  2. 기본 근무시간과 등록 기록을 확인합니다.
  3. 휴가 입력 또는 근무변경 입력을 선택합니다.
  4. 날짜·단위·시간과 필요한 경우 선택 메모를 확인하고 저장합니다.
입력단위와 예시저장 후 변화
휴가1일·반차·반반차 또는 시간 · 0.5시간(30분) 간격, 예: 1.5시간개인 달력에 휴가가 표시되고 조건에 따라 대근 수요 생성
대근시간 · 0.5시간 간격, 예: 12시간근무 기록과 주간 합계에 반영
교육·지원시간 · 0.5시간 간격, 예: 7.5시간선택일 상세와 근로시간 경고에 반영
메모 (선택)비워 두어도 저장 가능본인·관리자 상세에서만 확인, 월간·전체·공유 화면 비공개

30분은 0.5시간입니다. 1.25시간처럼 30분 단위가 아닌 값은 저장할 수 없습니다.

03

근무표 화면의 전체 근무표를 눌러 A/B/C/D조와 일반 상주·상주A·상주B 일정을 비교합니다. 개인 사유와 메모는 표시하지 않습니다.

04

휴가·대근 월간 현황

빈 달력 형태로 날짜별 휴가자와 현재 대근자 이름만 빠르게 확인합니다. 각 날짜에는 날짜 숫자와 주간조·야간조가 `주 C · 야 A`처럼 표시됩니다.

분홍 휴가
그날 휴가를 등록한 합성 인물
초록 대근
자율 등록했거나 관리자가 수정한 현재 대근자
미충원
필요 인원에서 현재 등록 인원을 뺀 값
  1. 휴가·대근 메뉴를 선택합니다.
  2. 날짜에서 이름 배경색과 주간조·야간조를 확인합니다.
  3. 날짜를 누르면 아래에서 휴가자·대근자·미충원을 다시 확인합니다.

실제 앱에서는 업무상 필요한 이름만 보이며 휴가 사유나 개인 메모는 이 화면에 표시하지 않습니다.

05

대근 등록·지원

대근 수요는 근무 공백을 채우기 위해 필요한 추가 인원입니다. 미충원은 필요 인원에서 현재 등록 인원을 뺀 값입니다.

  1. 날짜·조·주간/야간과 필요한 인원을 확인합니다.
  2. 현재 등록 인원과 예상 주간 근로시간을 확인합니다.
  3. 대근 등록을 누르면 관리자 승인 없이 현재 대근자로 바로 반영됩니다.
  4. 잘못 등록한 경우 등록 취소를 사용하고, 관리자가 대리 수정하면 수정된 결과를 표시합니다.
자동 생성 조건 예시

작업자가 기본 근무일에 휴가를 등록하고 `대근 필요`를 선택하면, 실제 앱은 해당 조와 주간/야간 근무에 맞는 수요를 자동으로 만들 수 있습니다. 휴무일이거나 대근 불필요를 선택하면 만들지 않습니다.

06

일정·공지

교육, 지원, 회사 일정과 중요 공지를 기간별로 확인합니다. 시작일과 종료일의 단위는 날짜이며, 예시는 2026-08-27~2026-08-28입니다. 대근 필요 인원이 1명 이상이면 일정과 수요를 연결할 수 있습니다.

07

역할별 작업 차이

역할가능한 작업제한
관리자계정·권한·조 이동·대리입력·운영 복구실제 운영 책임과 검증 필요
편집자공지·대근 수요 관리계정·권한 변경 불가
작업자본인 기록 관리·월간 현황 확인·대근 자율 등록다른 사람 기록 수정 불가
배우자공유받은 일정 읽기개인 메모·휴가자 이름·대근·관리 기능 접근 불가

조 이동 적용일은 새 조 규칙이 시작되는 첫날입니다. 과거 기록은 지우지 않고 적용일부터 기본 근무표가 바뀝니다.

08

오류·정정·복구

  • 필수 날짜·인원·시간이 없으면 저장을 막는 오류를 먼저 고칩니다.
  • 근로시간 주의는 저장할 수 있지만 실제 운영 판단이 필요합니다.
  • 잘못 저장했다면 해당 기록의 수정·취소·삭제 절차를 사용합니다.
  • 운영 앱에서는 복원 전에 현재 개인 데이터를 안전 백업해야 합니다.
  • 공개 데모는 새로고침하면 최초 합성 상태로 돌아갑니다.
